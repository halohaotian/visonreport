# VisonReport i18n Design

## Goal

Add bilingual support (English + Chinese) to VisonReport with English as default, using URL-prefix routing (`/en/...`, `/zh/...`).

## Approach: No-library (Next.js 16 official pattern)

Next.js 16 renamed `middleware` to `proxy` and the official i18n docs recommend a simple no-library approach using `getDictionary()` with dynamic imports. This avoids `next-intl` compatibility risks with Next.js 16.

All 7 pages are `'use client'` components, so we use a React context to provide translations.

## Architecture

```
dictionaries/
  en.json                # English translations
  zh.json                # Chinese translations
  index.ts               # getDictionary() + type exports
src/
  proxy.ts               # locale detection + redirect (Next.js 16 proxy convention)
  components/
    LanguageSwitcher.tsx  # EN | 中 toggle component
  app/
    [locale]/             # dynamic locale segment
      layout.tsx          # root layout with locale + TranslationProvider
      page.tsx            # landing page
      (auth)/
        login/page.tsx
        register/page.tsx
        pricing/page.tsx
      admin/page.tsx
      visualize/page.tsx
    api/                  # unchanged — no locale prefix
```

## Proxy (replaces middleware)

```ts
// src/proxy.ts — Next.js 16 uses proxy.ts, not middleware.ts
import { NextResponse } from 'next/server';

const locales = ['en', 'zh'];
const defaultLocale = 'en';

export function proxy(request) {
  const { pathname } = request.nextUrl;
  const pathnameHasLocale = locales.some(
    (locale) => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`
  );
  if (pathnameHasLocale) return;
  request.nextUrl.pathname = `/${defaultLocale}${pathname}`;
  return NextResponse.redirect(request.nextUrl);
}

export const config = {
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico).*)'],
};
```

## Dictionary Loading

```ts
// dictionaries/index.ts
import 'server-only';

const dictionaries = {
  en: () => import('./en.json').then((m) => m.default),
  zh: () => import('./zh.json').then((m) => m.default),
};

export type Locale = keyof typeof dictionaries;
export const locales = Object.keys(dictionaries) as Locale[];
export const defaultLocale: Locale = 'en';

export const hasLocale = (locale: string): locale is Locale =>
  locale in dictionaries;

export const getDictionary = async (locale: Locale) => dictionaries[locale]();
```

## Translation Provider (client-side)

Since all pages are `'use client'`, we create a simple context:

```tsx
// src/components/TranslationProvider.tsx
'use client';
import { createContext, useContext } from 'react';

const TranslationContext = createContext<Record<string, any>>({});
export const useTranslations = (namespace: string) => {
  const dict = useContext(TranslationContext);
  return dict[namespace] ?? {};
};

export function TranslationProvider({ dict, children }) {
  return (
    <TranslationContext.Provider value={dict}>
      {children}
    </TranslationContext.Provider>
  );
}
```

## Layout Structure

```tsx
// src/app/[locale]/layout.tsx
import { notFound } from 'next/navigation';
import { getDictionary, hasLocale, defaultLocale } from '@/dictionaries';
import { TranslationProvider } from '@/components/TranslationProvider';

export async function generateStaticParams() {
  return [{ locale: 'en' }, { locale: 'zh' }];
}

export async function generateMetadata({ params }) {
  const { locale } = await params;
  const isEn = locale === 'en';
  return {
    title: isEn ? 'VisonReport — Visual Requirement Intelligence' : 'VisonReport — 需求全景可视化',
    description: isEn ? 'Transform requirements into visual architecture diagrams with AI.' : '上传需求文档，AI一键生成项目需求全景可视化图。',
    alternates: {
      languages: { en: '/en', zh: '/zh' },
    },
  };
}

export default async function LocaleLayout({ children, params }) {
  const { locale } = await params;
  if (!hasLocale(locale)) notFound();
  const dict = await getDictionary(locale);
  return (
    <html lang={locale === 'zh' ? 'zh-CN' : 'en'}>
      <body>
        <TranslationProvider dict={dict}>
          {children}
        </TranslationProvider>
      </body>
    </html>
  );
}
```

## Routing Rules

| URL            | Behavior                     |
|----------------|------------------------------|
| `/`            | redirect to `/en`            |
| `/en`          | English landing page         |
| `/zh`          | Chinese landing page         |
| `/en/login`    | English login                |
| `/zh/admin`    | Chinese admin dashboard      |
| `/api/*`       | unchanged, no locale prefix  |

## Language Switcher

Simple component in page header: `EN | 中`. Replaces locale segment in current path (`/en/...` ↔ `/zh/...`).

## Navigation Link Updates

All hardcoded `href="/login"`, `href="/admin"`, etc. must be prefixed with `/${locale}/`. Programmatic redirects (`window.location.href = '/login'`) must also include locale prefix. This applies to ~10 navigation links and ~5 programmatic redirects across all pages.

## Metadata & SEO

- `generateMetadata()` returns locale-specific title/description
- `<html lang>` set dynamically (`en` or `zh-CN`)
- `hreflang` alternate links for SEO

## What Changes

- All 7 page files moved into `app/[locale]/` with `useTranslations()` calls
- All hardcoded navigation `href` and `window.location.href` prefixed with locale
- New `proxy.ts` for locale routing
- New `dictionaries/` directory with en.json, zh.json, index.ts
- New `TranslationProvider` and `LanguageSwitcher` components
- `layout.tsx` restructured as `app/[locale]/layout.tsx`
- Metadata internationalized via `generateMetadata()`

## What Does NOT Change

- `src/lib/db.ts` — pure data operations
- `src/lib/auth.ts` — pure utility functions
- `src/lib/ai-parser.ts` — AI prompts kept in Chinese (for AI model, not user-facing)
- `src/app/api/*` — routes stay at root, no locale prefix; error messages stay in Chinese
- `globals.css`, `postcss.config.mjs`, `tailwind.config` — styles unchanged

## Scope

- 7 page files to refactor (move + replace hardcoded text)
- ~363 strings to extract and translate
- ~10 navigation hrefs + ~5 programmatic redirects to add locale prefix
- 5 new infrastructure files (proxy.ts, dictionaries/*, TranslationProvider, LanguageSwitcher)
